# ゲームプラン v0.4

作成：2026-11-10　状態：検討稿。【決定】はユーザーが選んだもの、【案】は提案で未確定。

## 0. 前提

- 【決定】ジャンル：**ローグライク・ハクスラ**（リアルタイム）。**ドロップが大量に出る爽快感（ドパ要素）を込みにする**
- 【決定】対象：Android と PC。iPhone は Mac がないため後回し（第8章）
- 【決定】エンジン：Unity 6 LTS 系
- 【決定】規模：小さく1本。初クリアまで約1時間
- 【決定】見た目：ドット絵。タイルは 16×16 で一旦進める
- 【決定】操作：縦持ち片手。移動と回避は手動、通常攻撃は自動。スキルは手動か、クールダウン明けの自動発動かを選べる
- 【決定】明るさ：全員共通の基本値から始め、スキルやアイテムで広げる。体力とは連動させない
- 【決定】Unityプロジェクトはこのリポジトリ（vofrpg）に置く

「ドパ要素」は「倒すとアイテムや火種がドバッとあふれ出し、レアが出た瞬間に気持ちいい」という意味で解釈している（違えば直す）。

## 1. コンセプト【案】

**仮題：『灯守（ひもり）』**

暗い塔を下りながら、押し寄せる敵の群れをなぎ倒し、あふれ出る装備を拾って自分だけの組み合わせを作るハクスラ。

- 気持ちよさの柱
  1. **群れをまとめて倒す**：画面いっぱいの敵を一気に消し飛ばす
  2. **ドロップの噴水**：強い敵や宝箱から装備と火種があふれ出る
  3. **レアの瞬間**：光の柱・専用の音・画面の揺れで「当たり」を知らせる
  4. **組み合わせが壊れる**：装備の効果が重なって、急に強くなる瞬間がある
- 明るさは**装備の能力の一つ**として残す。明るさの範囲＝見える範囲＝自動攻撃の届く範囲

## 2. 操作（スマホ・縦持ち）【案】

| 操作 | 方法 |
| --- | --- |
| 移動 | 画面を親指で押してずらす（押した場所が仮想スティックの中心） |
| 通常攻撃 | 自動。明るさの範囲内の敵を狙う（狙い方は装備で変わる） |
| 回避 | 画面をはじく。短い無敵時間あり |
| スキル | 画面下のボタン（最大3つ）。スキルごとに「手動」「オート」を切り替え |
| 拾う | 近づくだけで自動で吸い寄せる。装備は自動で鞄へ入る |
| 装備の入れ替え | 一時停止して鞄を開く。今の装備より強いものには矢印を出す |

PC版はキーボード（WASD／矢印、回避はスペース、スキルは1〜3、鞄はTab）とゲームパッドに対応する。

## 3. ゲームの流れ

```
拠点（塔の入口）
 └ 出撃 → 第1層 → 第2層 → 第3層 → 第4層 → 最下層（ボス）
            各層：群れとの戦闘 → 精鋭・宝箱でドロップの噴水 → 祭壇 → 下り階段
 └ 死亡／クリア → 拠点へ戻る（持ち帰れるものは 4.5）
```

| 項目 | 目安【案】 |
| --- | --- |
| 1回の挑戦 | 12〜15分 |
| 初クリアまで | 3〜5回の挑戦（約1時間） |
| 層の数 | 5層（4層＋ボス層） |
| 1層の構成 | 広めの部屋4〜6個。部屋に入ると敵の波が来る |
| 画面内の敵 | 通常 30〜60体、多い場面で 100体前後 |
| 中断 | アプリを閉じても、その層の最初から再開できる |

## 4. 主な仕組み【案】

### 4.1 装備
- 装備欄は5つ：**武器／ランタン／防具／指輪×2**
  - 武器：通常攻撃の形が変わる（単発・連射・扇状・貫通の槍など）
  - ランタン：明るさと、火の属性（炎・氷・雷・影）を決める
- 珍しさは5段階。色で区別する

| 段階 | 色 | 付く効果 | 出る頻度（目安） |
| --- | --- | --- | --- |
| 並 | 白 | 0〜1個 | とても多い |
| 良 | 青 | 1〜2個 | 多い |
| 稀 | 黄 | 3〜4個 | ときどき |
| 伝承 | 橙 | 3個＋固有効果 | まれ |
| 灯宝 | 紫 | 固有効果のみ。組み合わせを大きく変える | とてもまれ |

- 効果の例：攻撃力＋%、攻撃速度＋%、明るさ＋1、会心率、移動速度、スキルのクールダウン短縮、倒した敵が爆発する、拾った火種で回復、など。初回は30種類程度
- 固有効果の例：「通常攻撃が3回に1回、スキルの火の輪を出す」「明るさの外の敵にもダメージが届く」「回避した場所に火の柱が残る」

### 4.2 ドパ要素（演出と仕組み）
- **ドロップの噴水**：精鋭・宝箱・ボスを倒すと、装備と火種が放物線を描いて一斉にあふれる
- **当たりの演出**：稀以上は光の柱、伝承以上は専用の音と短い画面の揺れ、灯宝は一瞬スローになる
- **黄金の敵**：たまに出る逃げ回る敵。倒すと火種が大量に出る
- **宝の間**：ときどき出る特別な部屋。敵の波を全部倒すと宝箱が並ぶ
- **ダメージの数字**、ヒットストップ（当てた瞬間のわずかな停止）、群れが一気に消える効果音
- **スマホ向けの手間削減**：拾うのは自動、並の装備は自動で火種に変える設定、比較矢印、一括分解

### 4.3 明るさ
- 基本値は全員共通（例：半径3マス）。ランタン・効果・スキルで広げる
- 明るさの外の敵はぼんやり見えるだけで、通常攻撃が届かない
- 明るさを一時的に縮める敵（闇撒き）がいる

### 4.4 スキル・祭壇
- スキル：最大3つ。宝箱や祭壇で手に入る。例：火の輪、灯矢、照らし（数秒だけ明るさを大きく広げる）、火柱。初回は6種類
- 祭壇：火種を払い、3つの強化から1つ選ぶ（その挑戦のあいだだけ有効）。初回は12種類

### 4.5 持ち帰れるもの（要判断）
ローグライクでは毎回ゼロから始まり、ハクスラでは集めた装備が積み上がる。この二つの折り合いをどう付けるか、次の3案から選ぶ。

| 案 | 内容 | 向いている遊び |
| --- | --- | --- |
| A | 装備は挑戦のあいだだけ。持ち帰るのは「残り火」だけで、新しい装備や効果の解放に使う | ローグライク寄り。毎回の組み合わせ作りが主役 |
| B | 帰還した装備から1つだけ倉庫へ持ち帰れる。次の挑戦で持ち込める | 中間。当たり装備が次の挑戦の楽しみになる |
| C | 装備はすべて持ち帰れる。挑戦の途中で死ぬと、その挑戦で拾った分は失う | ハクスラ寄り。集める楽しみが主役 |

【提案】小さく1本で「毎回ドパの気持ちよさ」を味わえる **A か B**。

### 4.6 敵（初回は8種類＋精鋭の変化＋ボス1体）
- 群れの雑魚：数で押してくる。倒すと気持ちよく弾ける
- 明るさと関わる敵：影法師（明かりの外でしか動かない）、蛾（明るいほど群がる）、闇撒き
- 精鋭：通常の敵に「速い」「硬い」「分裂する」などの性質が付いた強い敵。ドロップの噴水が出る
- ボス：塔の底の「消えない炎」

## 5. 見た目【決定：16×16で一旦進める】

- 2Dの見下ろし視点、ドット絵、タイル 16×16
- 縦画面の内部の解像度は 180×390 前後。横に約11マス見える
- 光の表現：URP の 2D Light でランタンの光と暗闇を描く。ドロップの光の柱もここで表す
- 画面比率が機種ごとに違うため、余白は背景で埋め、ドットがにじまない整数倍で拡大する

## 6. 技術方針【案】

| 項目 | 方針 |
| --- | --- |
| Unity | Unity 6 LTS 系、URP（2D Renderer）、2D Pixel Perfect |
| 対象 | Android（主）、PC（Windows） |
| 大量の敵と弾 | 生成・破棄をくり返さず使い回す（オブジェクトプール）。当たり判定は簡単な円同士で計算する。数百体で重いときは処理方式を見直す |
| 大量のドロップ | 画面上のドロップは上限を決め、古い並の装備から火種に変える |
| 装備 | 効果の定義を ScriptableObject で作り、拾った装備は「種類＋珍しさ＋付いた効果と数値」のデータで持つ |
| マップ | Tilemap。部屋を並べて廊下でつなぐ方式。乱数はシード指定可 |
| 入力 | Input System。タッチ、キーボード、ゲームパッド |
| 保存 | 解放の状態・倉庫・中断した層の情報を JSON で保存 |
| 性能 | 中くらいのAndroid端末で、敵100体前後でも60fpsを目標 |

フォルダ構成（予定）：

```
Assets/
  Scripts/  Core/  Map/  Actors/  Combat/  Loot/  Light/  Skills/  Input/  UI/  Meta/
  Data/     Enemies/  Affixes/（効果）  Items/  Skills/  Boons/（強化）
  Art/  Audio/  Scenes/（Title, Hub, Run）
```

## 7. 進め方（マイルストーン）

| 段階 | 内容 | 完了の基準 |
| --- | --- | --- |
| M0 | Unityプロジェクトを作り、このリポジトリに置く。.gitignore、Android向けの設定 | 空のシーンがAndroidの縦画面で表示される |
| M1 | タッチで移動・回避、自動攻撃、固定の1部屋、雑魚の群れ（使い回し込み） | 50体の群れを倒しても重くならない |

| M3 | 明るさと暗闇、スキル2つ（手動／オート）、精鋭 | 明るさの外に攻撃が届かず、ランタンで広げられる |
| M4 | ランダム生成マップ、5層、祭壇、ボス、中断と再開 | 1回の挑戦が最初から最後まで遊べる |

※ ハクスラは「倒して拾う」の気持ちよさが命なので、M1〜M2で早めに確かめる順番にした。

## 9. 決めてほしいこと

1. 「ドパ要素」の解釈（大量ドロップとレアの瞬間の気持ちよさ）で合っているか
2. 持ち帰れるもの：A・B・C のどれにするか（4.5）
3. 通常攻撃は自動のままでよいか。ハクスラらしく「押している間だけ攻撃」にする手もある
4. 「暗いことにも強みがある」要素を入れるか（例：暗いと敵に気づかれにくい効果）
5. M0（Unityプロジェクトの土台作り）に進んでよいか

## 10. 注意

- この作業環境には Unity がないため、C# のコードや設定ファイルは書けても、動かして確かめることはできない。シーンやPrefabの最終的な設定と動作確認は、手元の Unity と実機でしてもらう必要がある。
- M0 のプロジェクト作成は、手元の Unity Hub で作ってもらうのが確実。こちらは .gitignore やフォルダ構成、スクリプトを用意する。

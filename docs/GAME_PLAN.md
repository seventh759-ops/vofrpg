# ゲームプラン v0.3

作成：2026-11-10　状態：検討稿。【決定】はユーザーが選んだもの、【案】は提案で未確定。

## 0. 前提

- 【決定】ジャンル：リアルタイムのローグライク
- 【決定】対象：Android と PC。iPhone は理想だが Mac がないため後回し（第7章）
- 【決定】エンジン：Unity 6 LTS 系
- 【決定】規模：小さく1本。全体で約1時間遊べる内容
- 【決定】見た目：ドット絵。タイルは 16×16 で一旦進める
- 【決定】操作：縦持ち片手。移動と回避は手動、通常攻撃は自動。スキルは手動でもクールダウン明けの自動発動でも使える
- 【決定】明るさ：全員共通の基本値から始め、スキルやアイテムで広げる。体力とは連動させない
- 【決定】Unityプロジェクトはこのリポジトリ（vofrpg）に置く

## 1. コンセプト【案】

**仮題：『灯守（ひもり）』**

光の届かない塔を、ランタンひとつで下っていくローグライク。

- **体力**と**明るさ**は別の数値。攻撃を受けても暗くはならない
- **明るさ**は全員が同じ基本値で始まり、拾った強化やアイテムで広げていく
- 明るさの範囲が「見える範囲」と「自動攻撃が届く範囲」になる。範囲の外の敵は姿がぼんやりとしか見えず、攻撃も届かない
- 迷いどころ：**明るく広げて安全に戦うか、暗いまま別の強みを伸ばすか**（4.2）

### 1.1 似た仕組みのゲーム（参考調査）

「体力が減ると灯りも小さくなる」仕組みは珍しくはなく、小規模な作品に例がある。

- LUMEN（ブラウザゲーム）：光が体力・視界・攻撃の射程を兼ね、時間とともに減る
- Nix Umbra：光を使うと体力も減っていく、ホラー寄りのローグライト
- ゲームジャムの作品にも「光が体力」という作品が複数ある

今回は体力と明るさを切り離すため、これらとは別の方向になる。

## 2. 操作（スマホ・縦持ち）【案】

| 操作 | 方法 |
| --- | --- |
| 移動 | 画面を親指で押してずらす（押した場所が仮想スティックの中心） |
| 通常攻撃 | 自動。明るさの範囲内で一番近い敵へ火を飛ばす |
| 回避 | 画面をはじく。短い無敵時間あり。使ったあと少し待つ |
| スキル | 画面下のボタン（最大3つ）。スキルごとに「手動」か「オート（クールダウン明けに自動発動）」を切り替えられる |
| 祭壇・メニュー | タップで選ぶ |

- PC版はキーボード（WASD／矢印、回避はスペース、スキルは1〜3）とゲームパッドに対応する
- オートの発動条件は、最初は「範囲内に敵がいれば撃つ」だけにする。条件を細かく決められるようにするかは後で判断

## 3. ゲームの流れ

```
拠点（塔の入口）
 └ 出撃 → 第1層 → 第2層 → 第3層 → 第4層 → 最下層（ボス）
            各層：探索・戦闘 → 祭壇（強化を選ぶ） → 下り階段
 └ 死亡／クリア → 拠点へ戻る（持ち帰った「残り火」で新しい強化などを解放）
```

| 項目 | 目安【案】 |
| --- | --- |
| 1回の挑戦 | 8〜12分 |
| 初クリアまで | 4〜6回の挑戦（合計約1時間） |
| 層の数 | 5層（4層＋ボス層） |
| 1層の広さ | 部屋5〜8個のランダム生成 |
| 中断 | アプリを閉じても、その層の最初から再開できる |

## 4. 主な仕組み【案】

### 4.1 体力
- 普通の体力。回復手段は少なめ（回復薬、祭壇での回復など）

### 4.2 明るさ
- 基本値は全員共通（例：半径3マス）
- 広げる手段：強化（「灯芯」：明るさ＋1マス）、アイテム（「油」：一定時間だけ広がる）、拾える燭台（その部屋だけ明るくなる）
- 暗いことの強みも用意して、明るさを広げない選び方にも意味を持たせる
  - 例：「影歩き」暗いと敵に気づかれにくい／「闇討ち」明るさの範囲の端にいる敵へのダメージが増える
- 明るさを一時的に縮める敵（闇撒き）を出し、明るさの価値を感じさせる

### 4.3 スキルと強化
- スキル：最大3つまで持てる。各層の祭壇や宝箱で手に入る。例：火の輪（周囲に火を放つ）、灯矢（遠くまで届く一撃）、照らし（数秒だけ明るさを大きく広げる）
- 強化：その挑戦のあいだだけ有効。祭壇で3つの中から1つ選ぶ。例：貫通、分火（3方向）、灯芯（明るさ＋）、反照（回避の直後に周りへ火を放つ）
- 初回の目安：スキル6種類、強化12種類
- 祭壇の対価（お金）は「灯」ではなく、敵が落とす「火種」にする

### 4.4 敵（初回は6〜8種類＋ボス1体）
- 明るさと関わる性質を持たせる
  - 影法師：明かりの外でしか動かない。照らすと止まる
  - 蛾：明るさが大きいほど群がってくる
  - 闇撒き：周りを暗くして、明るさを一時的に縮める
  - 灯喰い：近くにいると火種を奪う
- ボス：塔の底の「消えない炎」（行動は今後詰める）

### 4.5 恒久的な解放（ゆるめに）
- 死亡時、その挑戦で拾った「残り火」を持ち帰る
- 拠点で、新しいスキル・強化が出るようにしたり、開始時の道具を選べるようにしたりする
- 能力値を直接上げる成長は入れない

## 5. 見た目【決定：16×16で一旦進める】

- 2Dの見下ろし視点、ドット絵、タイル 16×16
- 縦画面の内部の解像度は 180×390 前後。横に約11マス見える
- 光の表現：URP の 2D Light でランタンの光と暗闇を描く
- 画面比率が機種ごとに違うため、余白は背景で埋め、ドットがにじまない整数倍で拡大する

## 6. 技術方針【案】

| 項目 | 方針 |
| --- | --- |
| Unity | Unity 6 LTS 系、URP（2D Renderer）、2D Pixel Perfect |
| 対象 | Android（主）、PC（Windows） |
| マップ | Tilemap。部屋を並べて廊下でつなぐ方式。乱数はシード指定可 |
| データ | 敵・スキル・強化・道具は ScriptableObject で定義 |
| 入力 | Input System。タッチ、キーボード、ゲームパッド |
| 保存 | 解放の状態と、中断した層の情報を JSON で保存 |
| 性能 | 中くらいのAndroid端末で60fpsを目標。光源の数を絞る |

フォルダ構成（予定）：

```
Assets/
  Scripts/  Core/  Map/  Actors/  Light/  Skills/  Input/  UI/  Meta/
  Data/     Enemies/  Skills/  Boons/（強化）  Items/
  Art/  Audio/  Scenes/（Title, Hub, Run）
```

## 9. 決めてほしいこと

1. 「暗いことにも強みがある」方向（4.2）を入れるか。入れないなら、明るさは純粋に広げるほど有利なものになる
2. 祭壇の対価を「火種」（敵が落とすもの）にしてよいか
3. 明るさの基本値（半径3マスくらいでよいか。実際に動かして決めてもよい）
4. M0（Unityプロジェクトの土台作り）に進んでよいか

## 10. 注意

- この作業環境には Unity がないため、C# のコードや設定ファイルは書けても、動かして確かめることはできない。シーンやPrefabの最終的な設定と動作確認は、手元の Unity と実機でしてもらう必要がある。
- M0 のプロジェクト作成は、手元の Unity Hub で作ってもらうのが確実。こちらは .gitignore やフォルダ構成、スクリプトを用意する。

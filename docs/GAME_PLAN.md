## 1. コンセプト【案】

**仮題：『灯守（ひもり）』**

光の届かない塔を、ランタンひとつで下っていく、リアルタイムのローグライク。

画面に出る数値は、ほぼ **「灯（ともしび）」ひとつだけ**。この1つの数値に3つの役割を持たせる。

| 役割 | 意味 | 具体例 |
| --- | --- | --- |
| 体力 | 攻撃を受けると灯が減る。0で死亡 | 敵に噛まれて 80 → 65 |
| 視界と射程 | 灯が多いほど明るく広く見え、遠くの敵まで攻撃が届く | 灯80なら半径5マス先まで見え、届く。灯30なら2マス |
| お金 | 祭壇で灯を払うと強化がもらえる | 灯を20払って「攻撃が貫通する」強化を得る。灯は 65 → 45 |

迷いどころは常に一つ。**「灯を払って強くなるか、残して明るさと命を保つか」**。
払えば強くなるが、暗くなって敵が見えにくくなり、攻撃も届きにくくなり、死にやすくもなる。

## 2. 操作（スマホ向け）【案】

- **縦持ち・片手**で遊べるようにする
- 画面のどこかを親指で押してずらす → その方向へ移動（押した場所が仮想スティックの中心になる）
- **攻撃は自動**：灯の届く範囲にいる一番近い敵へ、ランタンの火を自動で飛ばす
- 指を離して軽くはじく → 短い**回避**（無敵時間あり。使ったあと少し待つ）
- 祭壇やメニューはタップで選ぶ
- 「移動と回避に集中し、攻撃は灯の範囲で決まる」形にして、灯の量が戦い方に直結するようにする

## 3. ゲームの流れ

```
拠点（塔の入口）
 └ 出撃 → 第1層 → 第2層 → 第3層 → 第4層 → 最下層（ボス）
            各層：探索・戦闘 → 祭壇（灯と強化を交換） → 下り階段
 └ 死亡／クリア → 拠点へ戻る（持ち帰った「残り火」で新しい強化などを解放）
```

| 項目 | 目安【案】 |
| --- | --- |
| 1回の挑戦 | 8〜12分（スマホで遊びやすい長さ） |
| 初クリアまで | 4〜6回の挑戦（合計約1時間） |
| 層の数 | 5層（4層＋ボス層） |
| 1層の広さ | 部屋5〜8個のランダム生成 |
| 途中で中断 | アプリを閉じても、その層の最初から再開できる |

## 4. 主な仕組み【案】

### 4.1 灯
- 最大値100から始まる。視界と攻撃の届く半径は、灯の量に合わせて滑らかに変わる
- 階段を下りるたびに少し減る（同じ層に長く留まらせないため）
- 回復手段：燭台を見つける、倒した敵がまれに落とす「火種」を拾う

### 4.2 祭壇と強化（各層に1つ）
- 灯を払い、3つの強化の中から1つ選ぶ（その挑戦のあいだだけ有効）
- 例：貫通（火が敵を突き抜ける）、分火（火が3方向に飛ぶ）、影歩き（暗い場所で敵に気づかれにくい）、蛍（倒した敵が小さな明かりを残す）、反照（回避の直後に周りへ火を放つ）
- 初回は12種類程度。払わずに通り過ぎることもできる

### 4.3 敵（初回は6〜8種類＋ボス1体）
- 灯と関わる性質を持たせる
  - 灯喰い：近くにいると灯を吸い続ける
  - 影法師：明かりの外でしか動かない。照らすと止まる
  - 蛾：灯が多いほど群がってくる
  - 闇撒き：周りを暗くして、こちらの攻撃が届く範囲を一時的に縮める
- ボス：塔の底の「消えない炎」。プレイヤーの灯が少ないほど弱くなる。最後に「あえて灯を減らす」判断をさせる

### 4.4 恒久的な解放（ゆるめに）
- 死亡時、その挑戦で拾った「残り火」を持ち帰る
- 拠点で新しい強化を祭壇に出るようにしたり、開始時に持てる道具を増やしたりする
- 能力値を直接上げる成長は入れない（腕と知識で上達するゲームにする）

## 5. 見た目【案・タイルの大きさは要検討】

- 2Dの見下ろし視点、ドット絵
- 光の表現が主役：URP の 2D Light で、ランタンの光と周囲の暗闇を描く
- 縦画面での比較

| タイル | 内部の解像度（目安） | 横に見えるマス数 | 長所 | 短所 |
| --- | --- | --- | --- | --- |
| 16×16 | 180×390 前後 | 約11マス | 描く量が少ない。小さな画面でも読みやすい | キャラの表情や細部は出しにくい |
| 32×32 | 360×780 前後 | 約11マス | 細かい描き込みができる | 1枚あたりの作業量が約4倍 |

- 【提案】小さく1本を完成させる目的なら **16×16** を推す。iPhoneの画面比率は機種ごとに違うため、上下の余白を背景で埋めて、ドットがにじまない整数倍の拡大にする

## 6. 技術方針【案】

| 項目 | 方針 |
| --- | --- |
| Unity | Unity 6 LTS 系、URP（2D Renderer）、2D Pixel Perfect |
| 対象OS | iOS を主、Android も同じプロジェクトから出せるようにしておく |
| マップ | Tilemap。部屋を並べて廊下でつなぐ方式で生成。乱数はシード指定可 |
| データ | 敵・強化・道具は ScriptableObject で定義 |
| 入力 | Input System のタッチ入力（エディタではマウスとキーボードで代用） |
| 保存 | 解放の状態と、中断した層の情報を JSON で端末に保存 |
| 性能 | 古めのiPhoneでも60fpsを目標。光源の数を絞る |

フォルダ構成（予定）：

```
Assets/
  Scripts/  Core/  Map/  Actors/  Light/  Input/  UI/  Meta/
  Data/     Enemies/  Boons/（強化）  Items/
  Art/  Audio/  Scenes/（Title, Hub, Run）
```

## 7. iPhoneで配信するために必要なもの

- **Mac**：iOS向けのビルドは Mac 上の Xcode でしか作れない
- **Apple Developer Program**：年会費あり（日本では約1万3千円/年。最新額は要確認）。自分のiPhoneへ一時的に入れるだけなら無料でもできるが、ストアやTestFlight（テスト配信）には必要
- 流れ：Unity で iOS 向けに書き出す → Xcode でビルド → TestFlight で自分の端末に入れて試す → App Store の審査に出す
- Mac がない場合の代わり：Unity Build Automation などのクラウドビルドを使う方法がある（要確認）
